# נוהל אבטחת מידע (תקנה 4)

> **טיוטה** לאישור הממונה. את הנוהל מעבירים לכל מי שמקבל הרשאת גישה, וכל אחד מהם חותם שקרא.

## בקרות קיימות במערכת
| נושא | מה מיושם | איפה בקוד |
|---|---|---|
| הצפנה במנוחה | AES-256-GCM לכל קובץ, ומפתח ראשי (`MASTER_KEY`) מחוץ למסד הנתונים | `apps/server/src/crypto.ts` |
| הצפנה בתעבורה | HTTPS. חיבור למסד הנתונים עם `sslmode=require` | `db.ts`, `wiring.ts` (בדיקת ייצור) |
| הזדהות | קוד SMS חד-פעמי מגובב, עם חסימה אחרי 5 ניסיונות ומגבלות קצב לטלפון ול-IP | `services/auth.ts` |
| הרשאות | בידוד לפי משק בית בכל שאילתה, ותביעה פרטית | `services/*` (בדיקות `members-privacy.test.ts`) |
| צוות | כניסה אישית לכל איש צוות. טוקן משותף חסום בייצור | `services/ops-auth.ts` |
| תיעוד | `audit_log` לכל קריאת קובץ, שינוי סטטוס, הסכמה ופעולת צוות | `services/audit.ts` |
| צמצום מידע | מחיקת קבצים לפי מדיניות שמירה. התראות בלי פרטים רפואיים | `services/maintenance.ts` |
| ניטור | Sentry בלי גוף בקשות ובלי מידע מזהה | `monitoring.ts` |
| גיבוי | גיבוי יומי של מסד הנתונים אצל הספק. שחזור נבדק פעם ברבעון | אצל הספק |

## חובות שוטפות
- **הרשאות:** סקירה פעם ברבעון. הסרה מ-`OPS_PHONES` ומהספקים ביום שמישהו עוזב.
- **עדכוני תוכנה:** כל שבוע, ו-`npm audit` בכל שינוי.
- **סקר סיכונים ומבדק חדירות:** לפני השקה, ואחר כך כל 18 חודשים (ברמה גבוהה).
- **הדרכה:** כל מי שמקבל הרשאה עובר הדרכת פרטיות ואבטחה לפני שמקבל גישה, ואחר כך פעם בשנה.
- **ספקים:** הסכם עיבוד (DPA) והתחייבות בכתב לפי תקנה 3 להעברה לחו"ל. ראו [vendors.md](vendors.md).
