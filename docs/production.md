# העלאה לאוויר: אפליקציה אמיתית, בלי מוקים

המסמך מחולק לשלושה חלקים:
1. מה כבר מוכן בקוד.
2. **מה צריך ממך**: חשבונות, פרטים והחלטות שרק בעל העסק יכול לתת.
3. איך מפעילים, צעד אחר צעד.

## 1. מה מוכן בקוד

| רכיב | מצב | איך מופעל |
|---|---|---|
| SMS אמיתי (Twilio) | ✅ | `TWILIO_*` |
| דוא"ל אמיתי (Resend) | ✅ | `RESEND_API_KEY`, `EMAIL_FROM` |
| אחסון מוצפן (Cloudflare R2 / S3) | ✅ | `S3_*` |
| סליקה אמיתית (Cardcom): שמירת כרטיס בדף מאובטח, חיוב, קבלה אוטומטית, החזר | ✅ | `CARDCOM_*` |
| קריאת קבלות ב-AI (Claude), רק בהסכמת המשתמש | ✅ | `ANTHROPIC_API_KEY` |
| ניטור שגיאות (Sentry), שרת ואפליקציה, בלי מידע רפואי | ✅ | `SENTRY_DSN`, `EXPO_PUBLIC_SENTRY_DSN` |
| קטלוג כיסויים מחקרי עם מקור לכל ערך, והתאמה לפוליסה של המשתמש | ✅ | אוטומטי. סקירה: [catalog-review.md](catalog-review.md) |
| מסמכים משפטיים (תנאים, פרטיות, ייפוי כוח, נגישות), הסכמות נפרדות, מחיקה אוטומטית של קבצים | ✅ טיוטות | `LEGAL_*`, `DPO_*`, `CONTACT_EMAIL` |
| כניסה אישית לכל איש צוות בממשק התפעול | ✅ | `OPS_PHONES` |
| אייקון, מסך פתיחה ומיתוג | ✅ | `apps/mobile/assets` (מקור: `assets/brand/mark.svg`) |
| **מצב ייצור:** השרת מסרב לעלות אם אחד השירותים עדיין מדומה, או אם חסרים פרטים משפטיים | ✅ | `NODE_ENV=production` |

## 2. מה צריך ממך ⬅️

### א. החלטות ופרטים
- [ ] **ישות משפטית:** עוסק פטור, עוסק מורשה או חברה. זה קובע גם את סוג הקבלה (`CARDCOM_DOCUMENT_TYPE`). נדרשים שם, מספר (ח.פ. או ע.מ.) וכתובת.
- [ ] **דוא"ל לפניות**, ו**ממונה הגנת פרטיות** (שם ודוא"ל). זה יכול להיות גורם חיצוני.
- [ ] **מספרי הטלפון של אנשי הצוות**, לממשק התפעול.
- [ ] **דומיין** (למשל `magiali.co.il`). מומלץ: כתובת קבועה, מייל מהדומיין, ואמינות מול המשתמשים.

### ב. חשבונות שצריך לפתוח

### ג. דברים שרק אדם יכול לעשות
- [ ] **עורך דין:** לעבור על טיוטות התנאים, הפרטיות וייפוי הכוח (`apps/server/legal/`) ועל [מזכר הדרישות](research/legal-requirements.md). השאלות הפתוחות החשובות: הסגת גבול מקצוע עריכת הדין, רישוי ביטוח, וייפוי כוח אלקטרוני.
- [ ] **סקירת קטלוג:** לפתוח כל קישור ב-[catalog-review.md](catalog-review.md) ולאשר את המספרים. אתרי הקופות היו חסומים מסביבת הפיתוח.
- [ ] **הסכמי עיבוד (DPA)** עם כל ספק: [compliance/vendors.md](compliance/vendors.md).
- [ ] **לאשר את מסמכי האבטחה** ([compliance/](compliance/)), ולבצע **מבדק חדירות** לפני השקה רחבה.
- [ ] **בדיקה מול Cardcom:** במסוף הבדיקות 1000, לבדוק ששמירת כרטיס מחזירה 4 ספרות אחרונות וסוג כרטיס. אחר כך חיוב אחד אמיתי וקטן במסוף שלך, והחזר שלו.

## 3. הפעלה, צעד אחר צעד

### שרת (Render)
1. ב-Render: **New → Blueprint** ← הריפו ← **Blueprint file path:** `render.production.yaml`.
2. Render יבקש את הערכים המסומנים `sync: false`. מזינים את מה שנאסף בסעיף 2.
3. אחרי הפריסה, הלוג צריך להראות:
   ```
   services: sms=twilio · email=resend · storage=s3 (...) · payments=cardcom (terminal ...) · extraction=claude · push=expo
   ```
   אם חסר משהו, השרת לא יעלה, ויכתוב בדיוק מה חסר.
4. **דומיין:** ב-Render ← Settings ← Custom Domain. אחר כך מגדירים `PUBLIC_BASE_URL=https://app.your-domain`.
5. **צוות:** נכנסים ל-`https://<הכתובת>/ops` עם הטלפון שמופיע ב-`OPS_PHONES` (קוד ב-SMS).

> סביבת ההדגמה (`render.yaml`) נשארת כמו שהיא, לבדיקות. כדאי להשאיר שתי סביבות נפרדות.

### אפליקציות (iOS / Android)
1. `cd apps/mobile && npx eas-cli@latest init`. הפקודה יוצרת `projectId`, שנדרש גם להתראות פוש.
2. ב-`eas.json` מחליפים את `EXPO_PUBLIC_API_URL` בכתובת השרת, וממלאים `EXPO_PUBLIC_SENTRY_DSN`.
3. `npx eas-cli@latest build --profile production --platform all`
4. `npx eas-cli@latest submit --platform ios` (וגם `android`).
5. **בחנויות:**
   - קישור למדיניות פרטיות: `https://<הכתובת>/legal/privacy`
   - דף מחיקת חשבון: `https://<הכתובת>/legal/delete-account` (חובה ב-Google)
   - הצהרת **Health apps** ו-**Data safety** (Google), ו-**App Privacy** (Apple). המידע לפי [compliance/database-definition.md](compliance/database-definition.md).
